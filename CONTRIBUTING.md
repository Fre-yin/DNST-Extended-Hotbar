# Contributing / Mitwirken

## Deutsch

Beiträge zu DNST Extended Hotbar und dem Extended Hotbar Helper sind willkommen: Fehlermeldungen, Verbesserungsvorschläge, Dokumentation, Übersetzungen und gezielte Codeänderungen.

Bitte beachte unseren [Verhaltenskodex](CODE_OF_CONDUCT.md). Beiträge und Rückfragen sind auf Deutsch oder Englisch möglich.

### Fehler melden

Prüfe zuerst die README, die aktuellen Release-Hinweise und bestehende Issues. Wenn der Fehler noch nicht gemeldet wurde, erstelle ein Issue mit:

- Betroffener Komponente: Hotbar oder Helper
- Genauer Hotbar- und Helper-Version, soweit relevant
- Spielversion bzw. Steam-Build sowie MelonLoader- und Windows-Version
- Schritten zur Reproduktion
- Erwartetem und tatsächlich beobachtetem Verhalten
- Anderen installierten Mods, soweit relevant
- Bereinigten Protokollen oder Screenshots, falls hilfreich

Veröffentliche keine Zugangsdaten, privaten Schlüssel oder persönlichen Spielstände. Entferne persönliche Informationen aus Anhängen. Teste Änderungen möglichst mit einer gesicherten Testkopie und bewahre deine Originalspielstände auf.

### Sicherheitslücken

Melde vermutete Sicherheitslücken vertraulich über den in unserer [Sicherheitsrichtlinie](https://github.com/Fre-yin/DNST-Extended-Hotbar/security/policy) beschriebenen Meldeweg. Erstelle dafür kein öffentliches Issue.

### Verbesserungen und Übersetzungen

Beschreibe bei Funktionswünschen das Problem, den gewünschten Ablauf und den Nutzen. Besprich größere Änderungen zuerst in einem Issue.

Bei Übersetzungen gib bitte Sprache, betroffene Ansicht, bisherigen Text und deinen Vorschlag an. Ein Screenshot hilft bei Platz- oder Darstellungsproblemen.

### Code und Pull Requests

- Halte Änderungen klein und auf ein Thema begrenzt.
- Nutze für deinen Vorschlag einen eigenen Branch und öffne einen Pull Request gegen `main`.
- Beachte die bestehenden Konventionen und die Entwickleranleitungen der betroffenen Komponente.
- Erkläre im Pull Request, was sich ändert und warum. Verlinke das zugehörige Issue, falls vorhanden.
- Führe passende Prüfungen durch und nenne die Ergebnisse sowie nicht durchgeführte Tests.
- Aktualisiere betroffene Dokumentation.
- Füge keine Spieldateien, persönlichen Spielstände, Zugangsdaten oder privaten Signierschlüssel hinzu. Vermeide erzeugte Builds und Release-Archive in Quellcode-Pull-Requests.

Hotbar und Helper werden unabhängig versioniert. Versionsänderungen, signierte Updatepakete und Veröffentlichungen werden mit dem Maintainer abgestimmt. Bestehende Release-Dateien und Tags dürfen nicht still ersetzt werden.

Das Projekt wird in der Freizeit betreut. Eine feste Bearbeitungsfrist oder die Übernahme jedes Vorschlags kann nicht zugesichert werden.

## English

Contributions to DNST Extended Hotbar and the Extended Hotbar Helper are welcome, including bug reports, suggestions, documentation, translations, and focused code changes.

Please follow our [Code of Conduct](CODE_OF_CONDUCT.md). Contributions and questions may be written in German or English.

### Reporting bugs

Check the README, current release notes, and existing issues first. If the problem has not been reported, open an issue with:

- Affected component: Hotbar or Helper
- Exact Hotbar and Helper versions, where relevant
- Game version or Steam build, plus MelonLoader and Windows versions
- Steps to reproduce the problem
- Expected and actual behavior
- Other installed mods, where relevant
- Sanitized logs or screenshots, if helpful

Do not publish credentials, private keys, or personal game saves. Remove personal information from attachments. Where possible, test changes using a backed-up test copy and preserve your original saves.

### Security vulnerabilities

Report suspected vulnerabilities privately using the reporting channel described in our [Security Policy](https://github.com/Fre-yin/DNST-Extended-Hotbar/security/policy). Do not open a public issue for a security vulnerability.

### Suggestions and translations

For feature requests, explain the problem, the desired workflow, and the benefit. Discuss substantial changes in an issue before implementing them.

For translations, include the language, affected screen, current text, and suggested replacement. Screenshots help with layout or space constraints.

### Code and pull requests

- Keep changes small and focused on one topic.
- Use a separate branch for your proposal and open a pull request against `main`.
- Follow existing conventions and the development instructions for the affected component.
- Explain what changes and why. Link the relevant issue, if any.
- Run appropriate checks and describe the results, including any tests not performed.
- Update affected documentation.
- Do not include game files, personal saves, credentials, or private signing keys. Keep generated builds and release archives out of source-code pull requests.

Hotbar and Helper use independent version numbers. Version changes, signed update packages, and releases are coordinated with the maintainer. Existing release assets and tags must not be silently replaced.

This project is maintained in spare time. Review times and acceptance of proposals are not guaranteed.
